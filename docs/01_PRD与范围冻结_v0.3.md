## 一、课题对齐与国网生态定位

### 1.1 课题 #60 核心要求对齐
本工具对应培训班课题清单 **#60（浙江）《浏览器智能操作与技能录制复用技术研究及应用》**：
- **核心研究内容**：浏览器页面轻量化感知、交互元素精准定位、自然语言指令解析（降低网页信息采集与模型交互开销）；网页操作录制、技能封装与复用；开发浏览器智能操作插件，实现跨页面、跨系统信息查询与数据填报自动执行及结果校验。
- **四项量化评价硬指标**：
  1. **元素定位准确率**（含页面轻微改版扰动下的命中率与歧义拦截率）；
  2. **任务执行成功率**（严格区分动作完成与业务结果核验成功）；
  3. **操作耗时**（首次录制封装耗时 vs 批量复用运行+人工监督耗时）；
  4. **模型交互开销对比**（调用次数、Token 消耗、DOM 语义压缩率）。

### 1.2 与国网现有路线的差异化定位（避免“重造轮子”）
| 参照系 | 现有痛点（国网内网实测） | SkillFlow v0.3 独特价值主张 |
|---|---|---|
| **OpenClaw（原生 Browser-Use）** | 5 步点击耗 ~20 万上下文、耗时 3–10 分钟、内网中小模型失败率高、跨系统难打通 | **不是替代 OpenClaw，而是补齐其内网 Web 执行短板**：录制编译态轻量调模型，回放运行态确定性执行，将 Token 降 90%+、速度压回人工同速，并支持导出 `SKILL.md` / MCP 工具反哺 OpenClaw 与省级商城 |
| **传统 RPA / 数字同事** | 少数骨干写死 XPath，UI 微改即失效；无语义理解与数据追问分析能力 | **人人可录、1→N 表格批量泛化、执行后明细可追问**：基层操作一遍即沉淀技能，结合多维语义定位增强抗改版韧性 |
| **光明大模型 / 内网 ≤284B 模型** | 72B/8K 及 30B–80B 模型在多轮全量 DOM Agent 场景极易崩溃 | **工程降维器**：轻量化 DOM 语义蒸馏 + 原子小 Schema（≤ 4K–6K Tokens）+ 确定性统计代码算账，让内网模型也能稳跑复杂业务 |

## 二、产品形态与 12 步核心闭环

- **一期交付形态**：**100% 纯 Chrome/Edge Manifest V3 Side Panel 插件**（零本地后台进程，最小化内网部署成本）；**二期演进路径**：通过 `Skill IR v0.3` 与 `ExecutionDriver` 接口解耦，支持向 `L2 chrome.debugger` 增强模式与 `L3 本地 Playwright/CDP 伴侣` 平滑升级（具体架构写入研究报告）。
- **12 步完整闭环**：
  1. **开启录制与站点授权**（支持跨多固定 Origin 站点）；
  2. **人工执行一遍典型业务操作**（支持跨系统跳转，遇到密码/登录仅生成语义占位 `auth_checkpoint`）；
  3. **轻量化 DOM 语义蒸馏**（提取标签、角色、候选定位器与容器结构，记录压缩率）；
  4. **AI 解析生成技能草稿**（目的描述、步骤映射、可变参数、批量循环体 `batchLoop` 边界、结果采集 `extractSpec` 与不确定项）；
  5. **人工审核并保存技能**（支持切换固定值/参数、脱敏载荷预览、校验规则编辑）；
  6. **自然语言匹配或列表选择复用**（用户输入一句话任务，通过 `matchSkill` 命中已有技能）；
  7. **动态表单 + 一句话智能补参 / CSV 导入**（`extractArgs` 解析已有参数与日期，缺失必填项生成精准追问或行级字段映射）；
  8. **执行计划不可变快照确认**（生成 `planHash`；批量写入支持**“预填不提交”**或**“先试跑前 2 条人工核验再放行剩余”**梯度确认）；
  9. **受控自动执行**（按 `batchLoop` 循环执行，逐条持久化状态账本；遇会话失效/验证码按 `authPolicy` 触发人工接管或临时内存填单后原位续跑）；
  10. **业务结果核验与结构化采集**（严格区分 `ACTION_COMPLETED` 与 L0–L3 业务验证，自动抽取结果表格或回执写入 `records`）；
  11. **执行日志与数据分布追问**（`planQuery` 转白名单确定性算子先计算，再由 `explainRun` 带 `evidenceRefs` 组织回答；无明细显式拒答）；
  12. **长期复用与生态反哺**（保留本地技能库，支持定位失效后单步元素重绑 Re-bind，支持导出标准 `SKILL.md` & MCP JSON）。

## 三、功能需求冻结清单（P0 / P1 / 报告二期 / 砍掉项）

### 3.1 P0 必做功能（窗口 1 核心交付）
| ID | 功能模块 | 冻结验收口径 |
|---|---|---|
| FR-01 | 跨站点授权与录制启停 | 支持多固定 Origin 按需授权；`tabs.onUpdated` 与 `RECORD_EVENT` 同队列持久化，保留路由 Hash 与白名单业务 Query。 |
| FR-02 | 去噪录制与轻量化 DOM 蒸馏 | 折叠同元素重复输入，保留合法连点与复选框状态；记录元素多维语义特征并生成精简快照（记录字节/Token 压缩率）。 |
| FR-03 | AI 技能草稿与脱敏预览 | `analyzeTrace` 输出意图、绑定 `stepId` 的参数候选、`batchLoop` 建议、`extractSpec` 建议与不确定项；外发模型前提供脱敏载荷预览；模型失败可回退规则编辑。 |
| FR-04 | 人工审核与技能库保存 | 支持查看/修改参数类型（含 `dataset` CSV）、固定值/变量切换、后置条件；禁止同名变量卡死；保存至 `chrome.storage.local`（配 `unlimitedStorage`）。 |
| FR-05 | 自然语言技能匹配（NL 启动） | 用户在复用区输入自然语言指令时，通过 `matchSkill` 返回匹配技能及置信度供一键确认加载（不直接盲跑）。 |
| FR-06 | 动态表单 + 一句话补参 & CSV 批量导入 | `extractArgs` 结合已有槽位和当前日期解析用户输入，仅追问缺失项；支持上传本地 CSV、表头→参数列映射与脏数据（空值/非法类型）前置检查。 |
| FR-07 | `planHash` 快照审批与梯度确认 | 后台校验 `planHash`；变参/变站点/变步骤即刻令审批失效；写操作支持“预填不提交”及批量**“先试跑 2 条核验 → 放行剩余”**，拒绝使用 `window.confirm`。 |
| FR-08 | `ExecutionDriver`（MV3 驱动）与多维定位 | 执行与 IR 解耦；定位按 `testId/stableId > aria/label > text > cssPath` 回退并校验**唯一性与可见性**；多命中报 `TARGET_AMBIGUOUS` 安全停止；支持 `outputVar` 跨步/跨系统传值。 |
| FR-09 | `auth_checkpoint` 双模式安全鉴权 | 密码永不录原值/不发模型/不落盘/不进日志。默认 **模式 A（人工接管）** 暂停等待人工完成登录/验证码后原位续跑；支持开关切换 **模式 B（内存临时密文填单）**，填入即销毁，遇验证码降级模式 A。 |
| FR-10 | 1→N 批量执行与逐条状态账本 | 区分一次性前置导航与循环体步骤，逐条落盘 `verified/failed/skipped/unknown`；遇 `UNKNOWN` 写状态严禁自动重试；支持断点手动核对后续跑剩余条目。 |
| FR-11 | 结构化结果采集与 L0–L3 核验 | `table-extractor` 抓取 HTML 表格行或回执单号/失败原因存入 `records`；严格区分动作完成与业务核验成功（识别页面 `error`/空结果提示）。 |
| FR-12 | 确定性统计与分布追问 | 通过 `planQuery` 将用户追问映射至白名单算子（计数/分组占比/失败原因排行/求和均值/异常行清单），代码算完由 `explainRun` 带证据作答；`records` 为空时明确拒答。 |
| FR-13 | 凭据与敏感词全局防护 | `isSensitive` 覆盖 `<label>` 文本与密码/OTP/身份证/手机号/户号/姓名/银行卡/账号等关键词；提示词注入隔离页面不可信文本；API Key 仅存 `chrome.storage.session`。 |
| FR-14 | 离线 Mock 保底与 ≤284B 容错 | 无网或模型超时时，可一键切换离线 Mock 模式完整演示闭环；真实模型层支持剥离 `<think>`、JSON 提取与 1 次带错重试。 |

### 3.2 P1 晚间冲刺加分项（碎片期 6 个晚间完成）

|---|---|---|

### 3.3 明确砍掉项（相对 v0.2，立省 6–8 人天）
1. ❌ **`v0.1 → v0.2` 存量技能自动迁移与回退**（原型期无存量生产用户，直接冻结干净的 v0.3 Schema）；
2. ❌ **6 任务 × 3 状态 = 18 实例全量跨竞品实测**（聚焦课题 #60 对应的 3 任务 × 4 指标 × 3 路线深度实测）；
3. ❌ **纯聊天式多轮填参外壳**（改为“一句话 NL 解析 + 动态结构化缺参表单”，更符合企业效率与小模型稳定性）；
4. ❌ **P1 关键帧 VLM 视觉分析与通用页面自恢复**（避免重上下文和长延时拖垮演示与 284B 以下内网模型）。

## 四、两大核心演示场景（S1 & S2）

- **S1 · 跨双系统信息查询与明细汇总**：
  - 在本地固定端口 **系统 A（`18761`：客户/电量查询系统）** 录制“输入单位与月份 → 点击查询 → 抓取结果表格”并跨页/跳转至 **系统 B（`18762`：台账核对页）** 补充查询；
  - 复用时输入“查 B 单位”，系统主动追问缺失月份并校验 `YYYY-MM` 格式，确认后自动查询并抓取明细表格，支持追问“共多少条、各供电所/电压等级记录分布、总电量合计”。
- **S2 · 1→N 批量台账填报、人工接管与异常分布追问**：
  - 示教录入 **1 条** 模拟工单/台账记录（可选包含一次登录 `auth_checkpoint`），AI 识别参数与 `batchLoop` 循环体；
  - 复用时上传 **10–20 条脱敏 CSV**（其中刻意包含 1–2 条超限/非法枚举导致系统 B 报错提示的异常数据），完成表头列映射；
  - 勾选“先试跑前 2 条”，确认 `planHash` 后自动完成前 2 条并在侧边栏核验页面真实落库回执，人工点击“放行剩余条目”后自动完成余下记录（中途可模拟一次登录态失效 → 人工接管登录后原位续跑）；
  - 结束后追问：“一共成功多少条、失败几条、按供电单位成功分布和失败原因占比分别是什么？”——系统基于结构化 `records` 精准计算并带行号证据作答。

## 五、冻结验收标准（UAT-01 ~ UAT-12）

| 用例 ID | 验证点 | 必须观察到的结果（可测可截屏） |
|---|---|---|
| UAT-01 | 双固定端口跨系统录制 | 在 `18761` 与 `18762` 跨站录制并保存技能；重启演示服务后已存技能仍可直接回放不失效。 |
| UAT-02 | 轻量化蒸馏与 AI 草稿 | DOM 快照显著压缩（记录压缩率）；草稿意图、参数与 `stepId` 映射正确，外发前可预览脱敏载荷。 |
| UAT-03 | NL 匹配与缺参追问 | 输入“查 B 单位”命中查询技能并仅追问缺失月份；“上个月”结合当前日期正确归一化；非法格式拦截。 |
| UAT-04 | `planHash` 审批门禁 | 未确认不能运行；确认后改动任意参数/CSV 行/目标站点，后台以 `PLAN_NOT_APPROVED` 拦截并要求重批。 |
| UAT-05 | 跨系统变量传递与查询复用 | 系统 A 查到的关键编号通过 `outputVar` 传入系统 B 完成关联查询，结果表抓取完整。 |
| UAT-06 | 1→N CSV 批量与梯度试跑 | 1 条录制 + 10 条 CSV 映射后，先试跑 2 条核验再放行剩余 8 条；支持“预填不提交”开关。 |
| UAT-07 | 动作完成 vs 业务核验区分 | 系统返回 `error` 或校验失败文案时，状态标为 `FAILED`/`ACTIONS_COMPLETED_UNVERIFIED`，绝不误报 `VERIFIED_SUCCESS`。 |
| UAT-08 | 确定性分布追问与无据拒答 | 批量完成后准确回答成功数、按单位分布及失败原因占比（与逐条账本 100% 一致）；无明细场景追问分布时明确拒答。 |
| UAT-09 | `auth_checkpoint` 与敏感保护 | 密码/身份证/手机号/户号（含 `<label>`）不进轨迹/存储/日志/模型；模式 A 挂起待人工登录续跑，模式 B 内存填单后即毁。 |
| UAT-10 | 故障安全中止与断点账本 | 批量途中关闭侧边栏、断网或遇 `UNKNOWN` 写入时安全停下，账本保留已跑记录，人工核对后可续跑剩余条目而不重提交未知项。 |
| UAT-11 | 定位安全失败与单步重绑 | 删掉或改版目标按钮导致无匹配或歧义时报 `TARGET_AMBIGUOUS`/`ACTION_FAILED` 停止，不误点相似按钮；支持单步 Re-bind 后恢复。 |
| UAT-12 | 生态导出与 ≤284B 容错 | 一键导出可用 `SKILL.md` & MCP JSON；模型返回 `<think>` 包裹/Markdown JSON 可正常解析，断网/超时可切 Mock 无崩溃。 |
