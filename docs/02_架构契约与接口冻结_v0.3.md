### 字段关键约束
- `parameters[].type` 枚举：`string | month | date | number | enum | dataset`。
- `steps[].action` 枚举：`navigate | fill | select | check | keypress | click | extract | auth_checkpoint | manual`（严禁出现 `executeScript` 等动态代码动作）。
- `steps[].target` 定位优先级（按从高到低依次命中，**动态 ID 如 `ext-gen*` / 长数字随机后缀降权跳过**）：
  1. `testId`（`[data-testid=...]`）
  2. `stableId`（非动态生成 ID）
  3. `ariaLabel` / 关联 `<label>` + `tag`
  4. `anchor`（邻近表头/行关键字相对锚点）+ `text`
  5. `cssPath`
  - 任一候选若命中 **>1 个可见且可用元素**且语义不一致，禁止静默点第一个，必须返回 **`TARGET_AMBIGUOUS`**。
- `extractSpec.mode` 支持两种：
  - `"table"`：用于查询页，通过 `containerSelector`（如 `#result-table`）及 `columns[]`（列索引或表头名）直接抓取二维明细写入 `records[]`；
  - `"receipt"`：用于填报页，每跑完 1 行 `batchLoop` 抓取页面回执与该行输入字段合并为 1 条 `RecordItem`。

## 三、`ExecutionDriver` 解耦接口与三级演进契约

上层业务模块（`plan-builder`、`run-controller`、`batch-runner`、`result-evaluator`）**严禁直接调用 `chrome.tabs`/`chrome.scripting`**，必须全部通过 `ExecutionDriver` 接口调用页面能力。

```ts
interface ExecutionDriver {
  readonly kind: 'mv3-content' | 'chrome-debugger' | 'local-companion-cdp';
  capabilities(): {
    trustedEvents: boolean;
    crossOriginIframe: boolean;
    nativeFileUpload: boolean;
    persistentBackgroundLoop: boolean;
  };
  ensureSession(allowedOrigins: string[]): Promise<{ tabId: number; currentOrigin: string }>;
  navigate(url: string, opts?: { waitUntil?: 'complete' }): Promise<{ finalUrl: string }>;
  distillDom(opts?: { maxNodes?: number; focusSelector?: string }): Promise<{
    rawBytes: number;
    distilledBytes: number;
    compressionRatio: number;
    snapshot: DistilledNode[];
  }>;
  executeStep(step: ResolvedStep): Promise<{
    ok: boolean;
    matchedLocator?: string;
    extractedValue?: string;
    errorCode?: string;
    message?: string;
  }>;
  extractRecords(spec: ExtractSpec, contextRow?: Record<string, unknown>): Promise<{
    records: Record<string, unknown>[];
    evidenceLevel: 'L0' | 'L1' | 'L2' | 'L3';
  }>;
  checkAuthState(checkpoint: AuthCheckpointStep): Promise<'AUTHENTICATED' | 'AUTH_REQUIRED'>;
}
```

### 三级演进路径（架构固定，按需启用）
| 级别 | 实现类 | 适用时期与部署成本 | 解决的能力上限 |
|---|---|---|---|
| **L1（本期唯一实现）** | `Mv3ContentScriptDriver` | 一期全部交付，零客户端、最小内网部署代价 | 覆盖同源/多固定 Origin 常规 Web 查询、批量录入、表格/回执抽取 |
| **L2（二期可选纯插件升级）** | `ChromeDebuggerDriver` | 仍无需本地进程，用户授权 `debugger` 权限即可启用 | 发出 `isTrusted=true` 真实键鼠事件、穿透 iframe/Shadow DOM、`DOM.setFileInputFiles` |
| **L3（二期重度岗位伴侣）** | `LocalCompanionCdpDriver` | 通过 Native Messaging / 本地 Host 对接 Playwright/CDP | 突破 SW 30s 休眠、500+ 条长任务无人值守、本地大 Excel 读写、桌面协同 |

## 四、`auth_checkpoint` 安全双模式与审批门禁契约

### 4.1 凭据零残留铁律
1. 录制阶段检测到 `input[type="password"]` 或命中敏感词（含关联 `<label>`）的登录控件时，**不采集任何 `value`**，合并生成 1 个 `auth_checkpoint` 节点。
2. 任何时候，密码/验证码/口令严禁写入 `chrome.storage.local`、轨迹 JSON、技能文件、`RunRecord` 日志或发往大模型。

### 4.2 双模式运行时流转（通过 `skill.authPolicy` 或面板开关切换）
- **模式 A（`manual_takeover`，默认，国网生产推荐）**：
  - 执行到 `auth_checkpoint` 先调 `driver.checkAuthState()`；若已登录（检测到 `loggedInIndicator` 且未在登录页），直接跳过记 `SKIPPED_AUTHENTICATED`；
  - 若需登录或遇到验证码/U-Key，运行状态机转为 **`PAUSED_AUTH_REQUIRED`**，在侧边栏显著提示“请直接在右侧业务网页完成 4A/SSO/验证码登录，完成后点击【我已登录，继续执行】”；用户点击继续后再次检测并原位续跑。
- **模式 B（`ephemeral_prompt`，测试/封闭调试可选开关）**：
  - 若未登录且页面仅含标准账号/密码框（无验证码/U-Key 特征），在侧边栏渲染纯本地受控表单（密码框使用 `type="password"`）请求用户本次输入；
  - 提交后**不经过 AI、不写 storage、不入日志**，由驱动直接填入页面并点击登录按钮，随后立即清空 JS 内存引用与侧边栏输入框；
  - 若登录后检测到仍停留在登录页或弹出短信/图形验证码，自动降级为模式 A 人工接管。

### 4.3 `planHash` 不可变审批快照与写操作分级
- `PlanSnapshot` 包含：`planId, skillId, skillVersion, targetOrigins, writeMode ('commit' | 'prefill_only' | 'pilot_then_batch'), argsDigest, batchRowCount, stepsDigest, createdAt`。
- `planHash = SHA-256(canonicalJson(PlanSnapshot))`（使用 Web Crypto API `crypto.subtle.digest`）。
- 用户点击“确认执行计划”后，`background.js` 在内存中登记 `approvedPlanHash`；执行器每步前比对当前计划 `planHash === approvedPlanHash`，不一致直接阻断报 `PLAN_NOT_APPROVED`。
- **写操作两种防护模式**：
  - **预填不提交（`prefill_only`）**：自动跳过 `risk === 'write_commit'` 的最终提交点击，停在页面待人工核对后手动点击；
  - **试跑后批量（`pilot_then_batch`）**：先执行第 `1..pilotCount`（默认 2）条并展示回执核验结果，用户点击“确认前 2 条无误，放行剩余 N 条”生成二段确认后再批量完成余下记录。

## 五、面向 ≤ 284B 内网模型的 `4+1` 原子 AI 接口契约

> 统一定名，彻底消除 v0.2 中 `explainRun` 与 `summarizeEvidence` 冲突；每个接口输入上下文硬控 **≤ 4K–6K Tokens**。

```ts
interface AIAdapter {
  matchSkill(input: {
    userQuery: string;
    skills: Array<{ id: string; name: string; intent: string; paramKeys: string[] }>;
  }): Promise<{ matchedSkillId: string | null; candidates: Array<{ skillId: string; score: number; reason: string }>; confidence: 'high'|'medium'|'low' }>;

  analyzeTrace(input: {
    traceSummary: SanitizedTraceSummary; // 已剥离敏感值，附带蒸馏后语义摘要
    pageContext: { title: string; headings: string[]; selectOptionsSample?: Record<string, string[]> };
  }): Promise<SkillDraftProposal>; // 仅映射已有 stepId，建议 parameterCandidates / batchLoopHint / extractHint / uncertainties

  extractArgs(input: {
    userText: string;
    parameters: ParameterSchema[];
    collectedArgs: Record<string, unknown>;
    lastQuestion: string | null;
    currentDate: string; // YYYY-MM-DD，用于解析“本月/上个月/昨天”
  }): Promise<ArgProposal>; // { providedArgs, missingRequired, nextQuestion, ambiguities }

  planQuery(input: {
    question: string;
    recordSchema: Array<{ key: string; label: string; type: 'string'|'number'|'status' }>;
    allowedOps: Array<'count'|'groupCount'|'ratio'|'sum'|'avg'|'filterTopErrors'|'listFailedRows'>;
  }): Promise<QueryPlan>; // { op, groupBy?, metricField?, filterStatus?, limit?, cannotComputeReason? }

  explainRun(input: {
    question: string;
    computedEvidence: EvidenceBundle; // 仅包含确定性代码算出的统计结果与脱敏行引用
  }): Promise<AnswerProposal>; // { answer, evidenceRefs, caveats }
}
```

### ≤ 284B 模型容错解析与降级流程（`lib/ai-client.js`）
1. **预处理剥离**：先移除 `<think>[\s\S]*?</think>`，再提取首尾 `{...}` 或 ` ```json ... ``` ` 代码块做 `JSON.parse`。
2. **Schema & 安全校验**：校验字段类型，并额外验证 `analyzeTrace` 返回的所有 `stepId` 均存在于原轨迹、`matchSkill` 返回的 `skillId` 存在于本地库、`planQuery.op` 在白名单内。
3. **1 次带错自动重试**：若解析或校验失败，把具体校验错误信息拼入纠错提示自动重试 1 次（总超时控制 ≤ 15s）。
4. **安全回退**：重试仍失败或网络不通时返回规范错误码（`AI_TIMEOUT`/`AI_SCHEMA_INVALID`），自动降级到规则/表单模式（本地正则命名 + 动态参数表单 + 关键词统计路由），绝不阻断录制资产与核心流程；提供面板“Mock 演示模式”一键切换开关。

### 统计计算规范（严禁 `Object.groupBy`）
在 `lib/result-qa.js` 中，所有分组必须使用兼容 Chrome 116 的标准 `reduce` 实现：
```js
function groupCount(records, key) {
  return records.reduce((acc, row) => {
    const k = String(row?.[key] ?? '(空)');
    acc[k] = (acc[k] || 0) + 1;
    return acc;
  }, Object.create(null));
}
```

### 统一错误码表（冻结）
| 错误码 | 触发条件 | 强制行为 |
|---|---|---|
| `AI_TIMEOUT` / `AI_SCHEMA_INVALID` / `AI_STEP_REF_UNKNOWN` | 模型超时、JSON 无效或越界引用 `stepId` | 拒收 AI 提案，保留原轨迹并回退规则/人工编辑 |
| `MISSING_PARAMETER` / `PARAMETER_INVALID` / `CSV_SCHEMA_INVALID` | 缺参、类型越界或 CSV 缺必填列/脏数据 | 追问或高亮标注错误行，阻止生成执行计划 |
| `PLAN_NOT_APPROVED` | 未点击批准、或批准后参数/站点/步骤变动 | 后台直接拒绝执行 |
| `SITE_NOT_ALLOWED` | 当前 Tab Origin 不在 `allowedOrigins` 或未授权 | 暂停并提示授权或切回目标站点 |
| `AUTH_REQUIRED` | 检测到登录页/会话过期/验证码/U-Key | 转 `PAUSED_AUTH_REQUIRED` 挂起待人工登录 |
| `TARGET_AMBIGUOUS` / `ACTION_FAILED` | 定位多个不一致元素或超时未找到元素 | 安全停步并高亮失败步，支持单步 Re-bind |
| `DOM_DISTILL_EMPTY` | 页面未能蒸馏出任何可见交互语义节点 | 提示检查站点/iframe 边界，不发送空包给模型 |
| `OUTCOME_UNVERIFIED` / `WRITE_OUTCOME_UNKNOWN` | 未达到后置条件或写入后无法确认落库状态 | 严禁标为成功；`UNKNOWN` 状态严禁自动重试 |
| `BATCH_ROW_FAILED` | 批量执行单条业务校验失败 | 记录该行失败原因到账本并继续/按策略暂停 |
| `USER_CANCELLED` | 用户主动点击终止 | 安全中止并保留已跑账本 |

在进入新模块开发前，必须按行号定位并优先修完以下 6 个实测缺陷：

1. **Bug 1（随机端口致历史技能全部失效）**
   - **现状**：`demo_server.py:19` 使用 `ThreadingHTTPServer(("127.0.0.1", 0), handler)` 每次分配随机端口，而 `panel.js:216-217` 强校验 `targetURL.origin !== activeURL.origin`，导致重启本地测试服务后所有已保存技能失效。
   - **修复**：改造 `demo_server.py` 默认分别在固定端口 **`18761`（系统 A）** 与 **`18762`（系统 B）** 启动双实例（支持 `--port-a` / `--port-b` 参数覆盖），`panel.js` 对跨多系统改用 `skill.allowedOrigins.includes(activeURL.origin)` 校验。
2. **Bug 2（`sanitizedUrl` 粗暴清空 Query 与 Hash）**
   - **现状**：`background.js:7-10` 与 `panel.js:6` 将 `u.search = ''; u.hash = '';` 一刀切清空，导致依赖 `#/route` 的 SPA 和 `?menuId=` 的老旧电网页面回放跳转偏离目标页。
   - **修复**：抽出统一 `sanitizer.sanitizeUrl(raw, allowedQueryKeys)`，保留路由 `hash`（剔除含 `token=`/`ticket=` 的 hash 片段）与白名单业务 `search` 参数，仅剔除 `token/ticket/session/password/auth/key` 等敏感键值对。
3. **Bug 3（`tabs.onUpdated` 绕过 `eventQueue` 并发写存储丢步）**
   - **现状**：`background.js:32-46` 直接读-改-写 `chrome.storage.local` 的 `currentSession`，未经过 `background.js:49` 的 `eventQueue` 串行队列，点击跳转瞬间与 `RECORD_EVENT` 并发覆写导致静默丢步。
   - **修复**：把 `tabs.onUpdated` 对 `currentSession` 的写入封装进同一个 `enqueueStorageWrite(fn)` 串行队列。
4. **Bug 4（三事件重录触发同名变量报错 + 去重漏判 `checked` 与合法连点）**
   - **现状**：`content.js:57-85` 同时监听 `input`、`change`、`focusout`，超过 `background.js:72` 的 600ms 去重窗口会录出多条同元素 `fill` 步骤，进而触发 `panel.js:118`“变量名不能重复”报错卡死；同时 `background.js:71-72` 未比对 `checked` 且误吞 600ms 内同按钮合法连点（如翻页/增行）。
   - **修复**：在录制后段/背景队列对同一元素连续无间隔的 `fill`/`select` 做最终值折叠合并（仅保留最后一次有效输入）；去重条件补充 `last.checked === safe.checked`，且**仅对 `fill/select` 折叠，不对 `click` 做同文本误吞**；变量命名去重时自动附加序号（如 `month_2`）。
5. **Bug 5（`isSensitive` 漏查 `<label>` 及电网敏感词 + `find()` 无唯一/可见性校验）**
   - **现状**：`content.js:38-42` `isSensitive()` 未拼接关联 `<label>` 文本且缺少“手机号/户号/姓名/身份证/银行卡/账号/金额”等敏感词；密码框回车（`content.js:53,89`）直接 `return` 漏录节点；`content.js:92-103` 的 `find()` 直接 `querySelector` 无唯一性与可见性校验，多行表格同名按钮会误点第一个。
   - **修复**：`isSensitive()` 合并 `targetFor(el).label` 与周边容器标签文本并扩充电网敏感词库；密码框合并生成 `auth_checkpoint`；`find()` 先过滤不可见/禁用元素（`offsetParent !== null` 或 `getClientRects().length > 0` 且 `!el.disabled`），若同一语义命中多个不一致元素返回 `TARGET_AMBIGUOUS`。
6. **Bug 6（TOCTOU 审批绕过、`window.confirm` 阻塞、`Object.groupBy` 版本冲突与 10MB 上限）**
   - **现状**：`panel.js:180-189` `preview()` 与 `panel.js:207` `execute()` 分别读取 UI 值存在 TOCTOU 绕过；`panel.js:208,233` 使用 `window.confirm` 易在 Side Panel 被拦截；`04_模型接口` 出现 Chrome 117+ 才支持的 `Object.groupBy`；`manifest.json` 缺 `unlimitedStorage`。
   - **修复**：改为后台校验 `planHash` 不可变快照；使用 Side Panel 内联审批卡片代替 `window.confirm`；统计全改用手写 `reduce`；`manifest.json` 新增 `"unlimitedStorage"` 权限。
