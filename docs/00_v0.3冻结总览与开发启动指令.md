## 二、v0.3 相对 v0.2 的 6 项冻结决策变更

1. **补齐 1→N 批量执行与表格/回执结构化采集（填平最大产品断层）**
   - `Skill IR v0.3` 新增 `dataset` 批量参数类型、`batchLoop`（前置动作/循环体/后置动作/前 2 条试跑核验/逐条复位规则）与 `extractSpec`（表格或回执明细抓取写入 `records`），真正跑通“单条示教 → 导入 CSV 批量录入 → 试跑核验后放行 → 按单位/失败原因追问数据分布”。
2. **强对齐课题 #60 漏考的硬指标与必考场景**
   - 把**跨双固定端口仿真系统（系统 A 查询 + 系统 B 填报）**拉回 P0 必做；
   - 新增 **轻量化 DOM 语义蒸馏器（`lib/dom-distiller.js`）** 并量化记录 DOM 压缩率；
   - 新增 **元素定位准确率** 评测，并将基准对比参照系从“仅对比小众插件”修正为 **SkillFlow v0.3 vs 全量 DOM 通用 Agent（对标 OpenClaw/Browser-Use）vs 传统 XPath RPA / 纯人工**，实证 Token 降 90%+ 与耗时优势；
   - 补齐 `matchSkill` 自然语言技能检索接口，闭合 F4“自然语言发起”断层。
3. **安全红线与 `auth_checkpoint` 双模式开关**
   - 焊死四不原则：**密码/口令永不录原值、永不发模型、永不写本地存储、永不进日志**；
   - 用统一的 `auth_checkpoint` 节点 + `authPolicy` 开关支持两种运行时策略：
     - **模式 A（`manual_takeover`，默认，国网合规态）**：复用浏览器已有 4A/SSO 会话；遇到登录页/会话失效/验证码/U-Key 时自动挂起暂停，提示人工在页面完成认证后原位续跑；
     - **模式 B（`ephemeral_prompt`，测试/封闭环境可选）**：侧边栏弹出纯本地密文输入框收集账号口令，**不经过 LLM、不落盘、不进日志**，内存中一次性填入页面后立即销毁；若页面仍弹验证码/U-Key，自动降级为模式 A。
4. **架构锁定“一期纯 MV3 交付 + 二期平滑演进混合架构”**
   - 一期只做 **100% 纯 MV3 浏览器插件**，零本地宿主进程，最小化内网部署代价；
   - 但第一天在代码中实现 `Skill IR v0.3` 与 `ExecutionDriver` 严格解耦（一期实现 `Mv3ContentScriptDriver`），运行账本逐步持久化，在设计文档与研究报告中明确 **L1 纯 MV3（一期）→ L2 纯插件 `chrome.debugger` 增强（二期可选）→ L3 本地 Playwright/CDP 伴侣（重度岗位选装）** 三级演进路径，核心逻辑后续可复用 75%–80%。
5. **面向 ≤ 284B 内网模型（DeepSeek-v4-flash）的 4 条工程铁律**
   - 单次模型输入硬控 **≤ 4K–6K Tokens**（纯文本轻量化摘要，P0 不做 VLM 截图）；
   - 模型调用拆为 **`4+1` 个单一职责扁平 JSON 原子接口**（`matchSkill`、`analyzeTrace`、`extractArgs`、`planQuery`、`explainRun`），**批量循环体内 0 次模型调用**；
   - 强容错解析：自动剥离 `<think>...</think>` 与 Markdown 代码围栏，Schema 校验失败带报错重试 1 次，仍失败则回退规则/表单兜底；
   - API Key 仅存 `chrome.storage.session`（不落持久存储），并内置离线 Mock/规则模式防路演断网。
6. **排期重锚至真实课表并果断砍冗余**
   - 按《电子版课表.pdf》真实有效时间（**窗口 1 仅 3 天编码 + 0.5 天打磨；碎片期仅 6 个正式自主研究晚间；12/12–17 研学真空期；12/18–19 定稿**），砍掉 **v0.1→v0.2 旧技能迁移、6×3=18 实例凑数实验、重型多轮聊天壳子、P1 VLM 与通用自动恢复**，立省 6–8 人天确保核心闭环稳妥交付。

## 三、不可违背的 8 条工程与安全红线

1. **禁止模型生成或注入远程 JS**：LLM 只允许输出绑定现有 `stepId` 的声明式 JSON 提案；`content.js` 只执行白名单内的确定性 DOM 动作（`fill`/`click`/`select`/`check`/`keypress`/`navigate`/`extract`/`auth_checkpoint`），严禁 `eval`、`new Function` 或执行模型生成的脚本。
2. **凭据零残留底线**：任何情况下（含模式 B），密码、OTP、Session Cookie、Token 均**不得写入轨迹、技能模板、运行日志、错误栈及外部/内网模型请求**。
3. **`planHash` 不可变审批门禁**：每次运行前由 `background.js` 对 `(skillId, skillVersion, targetOrigins, expandedArgsOrBatchDigest, stepsDigest, riskLevel)` 计算 `planHash`；页面参数、目标站点或步骤任一项变更，原审批立刻失效；写操作或批量写入未通过确认前，后台必须拒绝执行。
4. **无明细禁止猜测分布（防幻觉铁律）**：统计问答必须走“确定性代码计算（基于 `records`）→ 模型仅组织自然语言解释 + 带 `evidenceRefs`”。当 `records` 为空或缺少请求维度时，必须显式拒答。
5. **严禁 Chrome 117+ 独占语法**：`manifest.json` 锁定 `minimum_chrome_version: "116"`，代码及示例严禁使用 `Object.groupBy()`、`Array.prototype.toSorted` 之外的未验证新特性或超纲 API，分组聚合统一手写 `reduce`。
6. **状态一致性与防重放写入**：所有录制事件与 `tabs.onUpdated` 均须进入同一串行队列；批量运行每完成 1 条立即持久化账本；对于状态为 `UNKNOWN` 的写入操作，**严禁自动重试**，必须暂停待人工核对。
7. **严格站点白名单校验**：执行与采集必须同时校验 `sender.tab.id`、实时 `origin`、`skill.allowedOrigins` 与 `chrome.permissions.contains`，禁止未授权站点操作与无限定全网脚本注入。
8. **隔离工作边界**：所有新增/修改源码仅限 `SkillFlow_v0.3/source/` 目录内；严禁修改或删除工作区既有 `SkillFlow_MV3_*` 存档及其他课题材料。
