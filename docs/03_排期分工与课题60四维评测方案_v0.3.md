| 成员角色 | 专属负责文件 / 目录 | 核心交付职责 | 协作接口 |

## 三、课题 #60 四维量化对比评测方案（3 任务 × 4 硬指标 × 3 路线）

本评测直接响应《课题清单_V8.xlsx》#60 评价标准中的 **4 项量化硬指标**，取代 v0.2 冗余的 18 实例凑数实验。

### 3.1 评测任务集（3 个典型电网仿真任务）
| 任务编号 | 任务名称 | 核心考验点 |
|---|---|---|
| **T1** | **单系统条件查询与明细采集**（系统 A 查单位+月份 → 抽取结果表格 → 追问分组统计） | 轻量化感知、参数追问、结构化采集与无幻觉统计 |
| **T2** | **跨双系统协同 + 10 条 CSV 批量台账录入**（系统 A 取批号 → 系统 B 批量录入 10 条含 2 条异常 + 遇 1 次模拟会话失效人工接管 → 追问按单位与失败原因分布） | 跨 Origin 变量传递、1→N 批量稳定性、试跑/接管、`L2` 核验区分、零轮次批量执行开销 |
| **T3** | **页面轻改版与结构扰动测试**（开启系统 A 的“轻改版开关”：修改按钮 ID 为随机动态串、调整表单 DOM 嵌套层级） | **元素定位准确率**、抗改版韧性、歧义安全拦截（不误点） |

### 3.2 四项量化硬指标（对应课题打分表）
1. **元素定位准确率** = `正确命中目标交互元素次数 / 总定位尝试次数`（另单列“误点击次数”，误点击必须为 0，T3 页面改版后仍靠语义特征命中记入正面对比）；
2. **任务执行成功率** = **拆为两列报告**（`动作执行完成率` vs `业务结果核验准确率 L2`），单列记录高危误提交/敏感值泄漏次数（红线指标：必须为 0）；
3. **操作耗时** = **首次录制配置耗时（人工示教+审核）** 与 **单次/10 条批量复用总耗时（机器运行 + 人工确认监督）** 分别计时，对比人工纯手操基线计算提效倍数；
4. **模型交互开销对比** = 记录**模型调用次数**、**真实输入/输出 Token 数**及 **DOM 语义压缩率**（`(原始 HTML 字节 - 蒸馏后字节) / 原始 HTML 字节`）；若离线 Mock 环境无法获取真实 Token，明确标注 `NA` 并按字符/字节开销实测对比，绝不估算造假。

### 3.3 三条对比路线（同任务同环境对照）
| 对比路线 | 实验设定 | 预期揭示的课题核心结论 |
|---|---|---|
| **路线 1：SkillFlow v0.3（本方案）** | 录制编译期调轻量蒸馏+4 原子接口；回放期确定性执行（批量 10 条循环体 **0 次模型调用**） | 定位准确率高（多维语义）、业务核验严、批量耗时与人工相比提效显著、**Token 相比通用 Agent 下降 90%+** |
| **路线 2：全量 DOM 通用 Agent（对标 OpenClaw / Browser-Use 路线）** | 每步向 ≤284B 模型输入完整/未裁剪页面上下文进行多步自主规划（结合湖北/山东内网实测基线数据） | 每步重推理导致单任务 Token 飙升至数万~数十万、延迟高、T2 跨系统易迷失且中小模型成功率剧降 |
| **路线 3：传统刚性 XPath 脚本 / 纯人工操作** | 纯 XPath 回放（或 1 名熟练员工手动操作 10 条记录） | 纯人工耗时高易疲劳漏错；刚性 XPath 在 T3 改版开关打开后直接失效（0%），且无业务分布追问能力 |

## 四、研究报告必须补齐的竞品与二期演进章节指引

在提交结业研究报告时，基于 `docs/05_既有竞品调研与技术验证报告_v0.2参考.md` 务必补齐以下内容，以彻底堵住评委“技术视野窄”或“与 OpenClaw 撞车”的提问：
1. **补齐 5 类关键技术参照对比表**（在报告竞品章节增列“本地 Excel/CSV 批量驱动”与“结果结构化统计追问”两列）：
   - **Stagehand（MIT）**：剖析其 **Action Caching（AI 首次探索 → 缓存确定性脚本复用 → 页面变化自动 AI 自愈）** 与 SkillFlow 路线的异同，论证二期可引入该模式做异常按需自愈；
   - **Skyvern / Browser-Use**：对比其在复杂表单、Set-of-Marks 视觉标注与 A11y Tree 蒸馏上的取舍；
   - **Playwright MCP / Chrome DevTools MCP**：说明 2025–2026 主流浏览器自动化正转向 Accessibility Tree + MCP 协议，论证 SkillFlow 一键导出 `SKILL.md` & MCP JSON 的前瞻性；
   - **国内企业级 RPA+AI（影刀 RPA 等）**：对比纯桌面重客户端 vs 本课题“零安装纯浏览器插件”在国网终端合规准入上的部署优势；
   - **国网内部 OpenClaw（湖北/山东/信产/南瑞实测）**：直接引用推进会实测痛点数据（如山东 5 步耗 20 万上下文、跨系统零成功；湖北本地 80B 模型浏览器全败），确立 SkillFlow 作为“OpenClaw 生态内网 Web 技能供给底座”的清晰定位。
2. **写清二期生产级演进蓝图（不写本期代码）**：
   - 展示基于 `Skill IR v0.3` + `ExecutionDriver` 解耦设计的 **L1 纯 MV3 → L2 `chrome.debugger` → L3 本地 Playwright/CDP 伴侣** 三级演进图；
   - 说明 **DOM + 后台 HTTP API 双轨执行**、**国密赋码验签（课题 #11/#22）** 与 **内网统一模型网关身份透传** 落地路径。
